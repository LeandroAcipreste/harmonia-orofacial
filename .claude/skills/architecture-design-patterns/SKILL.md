# SOFTWARE ARCHITECTURE

- Priorize KISS, YAGNI, DRY, SOLID, alta coesão e baixo acoplamento.
- Prefira código simples, funções pequenas, módulos e composição antes de abstrações.
- Use Design Patterns somente quando resolverem um problema real. Nunca use Pattern apenas por formalidade.
- Preserve a arquitetura e o comportamento existentes ao modificar código.
- Leia somente os arquivos necessários para a tarefa.
- Não faça auditoria ou refatoração fora do escopo solicitado.
- Não crie abstrações, camadas, serviços, managers ou patterns antecipadamente.
- Considere Factory, Adapter, Facade, Strategy, Observer, State, Command, Repository e outros padrões quando o problema justificar.
- Prefira APIs nativas e soluções simples antes de criar abstrações próprias.
- Evite God Objects, God Functions, dependências circulares, estado global desnecessário e overengineering.
- A arquitetura deve evoluir conforme a complexidade real do projeto.
- Faça a menor alteração necessária para resolver corretamente o problema.
